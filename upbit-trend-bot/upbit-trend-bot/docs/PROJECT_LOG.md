# 업비트 AI 자동매매 프로젝트 진행 기록

2026-11-27 · 전우성

## 프로젝트 개요

업비트에서 BTC·ETH를 규칙 기반으로 자동 매매하는 시스템을 만들었다. 2026-11-27부터 AWS 클라우드 서버에서 실제 자금 5만 원으로 24시간 돌아가고 있다. 출발점은 퀀트 트레이딩 동아리 Forif에서 Freqtrade로 알고리즘 매매를 공부한 경험이다. 이를 국내 거래소인 업비트에서 실제로 운용하는 시스템으로 만들어 보기로 했다. 많이 알려진 "GPT에게 매번 매수·매도를 묻는" 방식 대신, 백테스트로 검증할 수 있는 규칙 기반 전략을 택했다. 재현성·비용·검증 가능성에서 낫다고 봤기 때문이다.

**목표**: 시장 상황이 바뀌어도 크게 잃지 않으면서 꾸준히 수익을 내는 것 (최대 낙폭 관리가 1순위).

**역할 분담**

| 역할 | 담당 | 내용 |
| --- | --- | --- |
| 기획·의사결정 | 전우성 | 목표 설정, 투자 금액 결정, 실거래 전환 판단, 계정·키 관리 |
| 설계·코딩·검증 | Claude | 전략 연구, 백테스트, 매매 엔진, 대시보드, 서버 배포 스크립트 |
| 실행 | 전우성 | 배치 파일 실행, 업비트·AWS·텔레그램 설정 |

**결과 요약**

- 채택 전략: 추세+모멘텀 필터 + 변동성 목표 비중 + -5% 손절
- 백테스트(2020-01~2026-11, BTC·ETH 50/50): 연 60.4%, 최대 낙폭 -24.1%, 샤프 1.66. 같은 기간 단순 보유는 연 44.5%, 최대 낙폭 -75.7%
- 운영: AWS Lightsail(시드니) 서버, 매시 7분 자동 실행, 텔레그램으로 원격 정지·재개·조회
- 모바일 대시보드: 실제 업비트 잔고, 수익률, 낙폭, 매매일지 자동 복기, 전략 수정 제안

## 진행 타임라인

아이디어부터 클라우드 실거래까지 이틀(2026-11-26~27)이 걸렸다. 무료로 할 수 있는 단계(데이터·전략·백테스트)를 먼저 끝내고, 돈이 드는 단계는 검증이 끝난 뒤에 넣었다.

| 단계 | 한 일 | 결과물 |
| --- | --- | --- |
| 1. 출발점 분석 | Forif에서 익힌 알고리즘 매매를 바탕으로 접근 방식 비교 (GPT 판단형 vs 규칙 기반) | 거래소는 업비트, 판단은 규칙 기반으로 결정 |
| 2. 데이터·백테스트 | 업비트 공개 API로 4시간봉·일봉 수집, 전략 5개 비교 | 추세+모멘텀이 압도적 1위 |
| 3. 견고성 검사 | 코인 6개, 파라미터 12조합, 손절폭, 공포·탐욕 지수 | 우연이 아닌 전략임을 확인 |
| 4. 모의투자 | PC에서 1시간마다 가상 매매 예약 실행 | 엔진 동작 확인 |
| 5. 전략 고도화 | 장세 전환·적응형·앙상블·변동성 목표 비교 | 변동성 목표 60% 채택 |
| 6. 대시보드 | 수익률·낙폭·매매일지·자동 복기·수정 제안 페이지 | HTML 대시보드 |
| 7. 실거래 전환 | 업비트 API 키 발급(출금 권한 없이), 한도 5만 원 | 첫 실주문 체결 |
| 8. 운영 보강 | 멈춤 감지, 손절 방식 연구, 텔레그램 알림·명령 | 매일 9시 요약, 원격 /stop |
| 9. 클라우드 이전 | AWS Lightsail 서버, 고정 IP, cron 자동 실행 | PC를 꺼도 24시간 운영 |
| 10. 모바일 대시보드 | 핸드폰용 재설계, 실제 업비트 잔고 표시 | 텔레그램 /dashboard |
| 11. 전체 점검 | 버그 8건 수정, 불필요한 파일 정리 | 현재 버전 |

## 전략 연구 과정

여섯 차례 백테스트를 거쳐 "단순한 추세추종 + 비중 조절 + 손절"로 수렴했다. 모든 테스트는 수수료 0.05%와 슬리피지 0.05%를 반영했다. 신호는 캔들 종가로 만들고 체결은 다음 캔들 시가로 해서 미래 정보를 쓰지 않았다.

| 차수 | 질문 | 핵심 결과 | 결론 |
| --- | --- | --- | --- |
| 1차 | 4시간봉(2025-08~2026-11 하락장)에서 어떤 전략이 버티나? | 보유 -49.5%, 추세+모멘텀 +11.4% | 하락장 방어는 추세추종이 우수 |
| 2차 | 일봉 8년(2018~2026)으로 늘리면? | 추세+모멘텀 연 57.7%, MDD -36.4% vs 보유 연 31.0%, MDD -74.1% | 일봉 추세+모멘텀을 기본 전략으로 |
| 3차 | BTC만 잘 되는 우연인가? | 6개 코인 모두 보유보다 낫고 MDD는 절반 수준. 파라미터 12조합에서 BTC 검증 구간 전부 플러스 | 우연이 아님 |
| 4차 | 공포·탐욕 지수를 더하면? | 필터 효과 0, 역발상 전략은 큰 손실 | 추가하지 않음 |
| 5차 | 장세에 따라 전략을 바꾸거나 비중을 조절하면? | 변동성 목표 60%가 MDD를 -35.7%에서 -24.1%로 줄이고 샤프 최고 | 변동성 목표 채택, 장세 전환·적응형·앙상블 기각 |
| 6차 | 손절은 장중이 좋을까, 종가가 좋을까? | 장중 -5%가 세 기간 모두 MDD 최소 | 현행 유지 |

후보별 수치와 채택 이유는 기능 설명서의 '투자 전략과 설정 이유' 섹션에 자세히 정리했다.

## 부딪힌 문제와 해결

실제 돈과 외부 서비스를 다루다 보니 백테스트에 없던 문제가 계속 나왔다. 대부분 실행 로그를 보고 원인을 찾았다.

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 주문 라이브러리 오류 | pyupbit가 업비트 응답 헤더 형식 변경을 못 따라감 | 업비트 API를 직접 호출하는 JWT 인증 모듈 자체 구현 |
| API 키 인증 실패 | .env에 예시 문구가 남아 키 길이가 51자 | 키 형태만 검사하는 진단 기능 추가 (키 내용은 열지 않음) |
| 5만 원 입금에 한도 100만 원 | 코인 한 개가 예산을 다 가져갈 위험 | 한도를 입금액에 맞추고, 바꾸면 다음 실행부터 자동 반영 |
| 백테스트 결과 왜곡 | 견고성 검사에서 지표를 검증 구간만으로 계산 / 손절이 역발상 테스트를 가림 | 전체 데이터로 지표 계산, 손절 없이 재검증 |
| 손절 후 반등 판정 오류 | 매도가가 아닌 평균 매수가와 비교해야 함 | 판정 기준 수정 |
| 휴대폰 대시보드 먹통 | iOS 파일 미리보기가 자바스크립트를 막음 | 상태를 서버에서 미리 계산, 탭을 CSS로 구현 |
| 일시 오류 시 하루 매매 누락 | 오류 전에 '오늘 처리함'을 기록 | 매매가 끝난 뒤 기록, 다음 시간 재시도 |
| 매도 주문 거절 위험 | 수량 반올림으로 잔고보다 많이 주문 | 소수점 8자리 내림 |
| 업데이트마다 봇 정지 | 재설치가 STOP 파일을 다시 만듦 | 첫 설치에만 정지 상태 |
| PC 설정이 서버에 안 감 | 배포 압축 파일이 미리 만들어져 있었음 | 업로드할 때 PC 파일로 새로 압축 |
| AWS 리전이 서울이 아님 | 새 가입 방식이라 시드니 자동 배정 | 시드니 IP에서도 업비트 API 정상 확인 후 진행 |

## 보안·운영 원칙

돈이 오가는 시스템이라 "문제가 생겨도 돈이 빠져나갈 길이 없게" 설계했다.

- **출금 권한 없음**: 업비트 API 키는 자산 조회·주문 조회·주문하기만 허용. 키가 유출돼도 돈을 밖으로 빼낼 수 없다.
- **IP 제한**: 키는 서버 고정 IP(와 집 IP)에서만 작동한다.
- **비밀 정보는 채팅에 없음**: API 키·텔레그램 토큰은 사용자가 .env 파일에 직접 입력했고, 코드는 키의 길이·형식만 검사한다. 서버 접속 키(.pem)도 공유하지 않는다.
- **금액 상한**: 봇이 쓸 수 있는 돈은 config의 한도(현재 5만 원)까지. 계좌에 더 있어도 건드리지 않는다.
- **이상하면 멈춤**: 하루 주문 6회 초과, 체결 확인 실패, 잔고 불일치 같은 이상 징후가 보이면 스스로 정지하고 알린다.
- **투자 결정은 사람이**: 투자 금액과 실거래 전환은 사용자가 직접 결정했다. 대시보드의 전략 수정 제안도 자동 적용되지 않고 사용자가 보고 판단한다.

**법적 검토**: 본인 계좌를 본인 돈으로 자동 매매하는 것은 업비트가 공식 API로 허용하는 이용 방식이다. 다만 타인의 돈을 운용하거나 프로그램을 판매·유료 제공하면 인가 문제가 생길 수 있다. 코인 양도소득 과세(22%)는 2027년 시행 예정인데, 2029년으로 2년 미루는 안은 아직 국회를 통과하지 않았다. 그래서 매매내역을 따로 보관한다.

## 배운 점과 한계, 다음 단계

가장 큰 교훈은 "복잡한 전략이 더 좋지 않다"는 것이다. 장세 전환, 적응형 파라미터, 앙상블, 공포·탐욕 지수 모두 단순한 추세추종을 이기지 못했다.

**배운 점**

- 수익률보다 최대 낙폭·샤프·Calmar를 함께 봐야 전략을 제대로 비교할 수 있다. 연 67.9%인 장세 전환보다 연 60.4%인 변동성 목표를 고른 이유다.
- 파라미터 하나가 아니라 주변 값 전체에서 잘 동작해야 과적합이 아니다.
- 백테스트는 시작일 뿐이다. 실거래는 주문 단위, API 오류, 서버 재시작 같은 문제가 훨씬 많다.

**한계**

- 여러 후보를 비교한 뒤 채택했으므로 선택 편향이 일부 있다. 현재 상장된 코인만 검사했으므로 생존 편향도 있다.
- 일봉 데이터라 장중 손절 체결가는 근사치다. 2024-12-03 계엄 플래시 크래시 같은 순간 급락에서는 훨씬 나쁜 가격에 체결될 수 있다.
- 추세추종이라 큰 상승장에서는 보유보다 덜 벌 수 있고, 횡보장에서는 작은 손실이 반복된다.
- 과거 성과가 미래 수익을 보장하지 않는다.
